> live, why they live there, and how the pieces connect*. Read this before
> editing the codebase — it will save you from re-inventing wheels that

## 1. Top-level layout

```
MathEdu-Unity-Game/
├── .gitignore
├── README.md                          ← Marketing / quick-start
├── Assets/                            ← The Unity project (you spend 95% of time here)
├── Docs/                              ← Project documentation
│   ├── InspectorWiring.md
│   ├── SESSION_LOG.md                 ← Make-playable session record
│   ├── UNITY_PROJECT_STRUCTURE.md     ← This file
│   ├── AI_AGENT_PROMPT_KG1_KG2.md
│   └── AI_AGENT_PROMPT_GRADE_4_5.md
├── Packages/
│   └── manifest.json                  ← Unity package dependencies (no 3rd-party!)
└── ProjectSettings/                   ← Per-project settings (orientation, etc.)
```

Why this matters:

- **`Assets/`** is everything Unity sees — every script, every scene, every
  ScriptableObject.
- **`Docs/`** is purely a GitHub-readable knowledge base; Unity ignores it.
- **`Packages/manifest.json`** is hand-curated. **Do not add third-party
  packages** without checking the task brief first — the project must
  build with stock Unity 6 modules + TextMeshPro only.
- **`ProjectSettings/`** is checked in so the build-target / orientation /
  reference-resolution are reproducible.

## 2. `Assets/` deep dive

```
Assets/
├── Scripts/                  ← All C# code
├── Scenes/                   ← 13 .unity files (generated by editor menu)
├── ScriptableObjects/        ← Generated content tree (generated by editor menu)
│   ├── MathDatabase.asset
│   ├── AvatarLibrary.asset
│   ├── Grades/
│   │   ├── Grade1/
│   │   ├── Grade2/
│   │   └── Grade3/
│   ├── Subjects/             ← Cross-cuts (rarely populated)
│   ├── Levels/               ← Cross-cuts (rarely populated)
│   └── Avatars/
├── Resources/                ← Auto-loaded at runtime
│   ├── MathDatabase.asset    ← Copy created by Build Default Database
│   ├── AvatarLibrary.asset
│   ├── UITheme.asset         ← Optional — drop your sprites here
│   ├── VFXLibrary.asset      ← Optional — drop Epic Toon FX prefabs here
│   └── Audio/                ← Drop .wav files here to override procedural SFX
├── Sprites/                  ← UI and Backgrounds (Layer Lab + custom packs)
│   ├── Backgrounds/
│   ├── UI/
│   └── Characters/
├── Epic Toon FX/             ← Optional vendor pack (particles)
└── Prefabs/                  ← Empty by design (UI is procedural)
```

### `Scenes/`

Every `.unity` file holds exactly **one** GameObject named `[SceneRoot]`
with a single MonoBehaviour attached. That MonoBehaviour rebuilds the
whole canvas at runtime via `UIFactory`. Pros:

- The `.unity` YAML stays tiny (~80 bytes); merges never conflict.
- One-line layout edits → no GUI surgery, just C# edits.
- Sub-classes can change theming without touching the scene.

### `ScriptableObjects/`

The procedural curriculum is materialised into asset files so designers
can inspect and tune individual questions. The editor menu **MathEdu →
Build Default Database** writes:

```
ScriptableObjects/Grades/Grade{N}/
  Grade_{N}.asset                       ← GradeData
  {Subject}/
    Subject_{Subject}.asset             ← SubjectData
    Level_01.asset .. Level_20.asset    ← LevelData × 20
```

### `Resources/`

Files in `Resources/` are loaded by name via `Resources.Load<T>(...)`.
That's how the runtime finds the database without any inspector wiring.
**Do not put gameplay logic here** — it's a content-only folder.

### `Prefabs/`

Empty by design. If you ever decide to swap procedural canvases for
designer-authored prefabs, this is where they'd go. Today there are
no prefabs.

## 3. Script namespaces and assembly definitions

Two assemblies:

| Asmdef | Namespace root | Compiles on |
|---|---|---|
| `Assets/Scripts/MathEdu.Runtime.asmdef` | `MathEdu.*` | All platforms |
| `Assets/Scripts/Editor/MathEdu.Editor.asmdef` | `MathEdu.EditorTools` | Editor only (referenced by `UnityEditor`) |

Sub-namespaces under `MathEdu.*`:

| Namespace | What's in it |
|---|---|
| `MathEdu.Data` | ScriptableObjects + serializable plain classes (`PlayerProfile`, `GameSession`, `MathQuestion`, etc.) |
| `MathEdu.Managers` | Singletons (`GameManager`, `AudioManager`, `ProgressManager`, `UIManager`, `VFXManager`, etc.) and the `HapticManager` static |
| `MathEdu.Modes` | Per-scene MonoBehaviour managers (`BootstrapManager`, `MainMenuManager`, `QuizModeManager`, etc.) |
| `MathEdu.Gameplay` | Abstract `GameplayManagerBase` shared by Practice/Quiz/Story/Speed |
| `MathEdu.UI` | UI helpers and widgets (`UIFactory`, `Timer`, `AnswerButton`, `StarRating`, `FadeOverlay`, etc.) |
| `MathEdu.Utility` | `QuestionGenerator`, `DatabaseBootstrapper`, `SaveSystem` |
| `MathEdu.EditorTools` | `DatabaseBuilderMenu`, `SceneBuilderMenu` (editor only) |

The reason for splitting into two assemblies: editor code uses
`UnityEditor.*` APIs that don't ship in builds. Putting them in their
own asmdef with `"includePlatforms": ["Editor"]` keeps the player build
clean.

## 4. `Assets/Scripts/` — folder by folder

```
Assets/Scripts/
├── Data/                              ← ScriptableObject definitions + plain classes
├── Utility/                           ← Static helpers (no MonoBehaviour)
├── Managers/                          ← Singletons, one instance per session
├── Modes/                             ← One per scene, MonoBehaviour
├── Gameplay/                          ← Shared base class for all MCQ modes
├── UI/                                ← Procedural UI helpers and widgets
└── Editor/                            ← Editor-only menus
```

### `Data/` — what each file owns

| File | Type | Purpose |
|---|---|---|
| `MathQuestion.cs` | serializable class | One MCQ: prompt, 4 options, correctIndex, hint, difficulty, visual hint. |
| `LevelData.cs` | ScriptableObject | A single level (id, level number, lesson text, story text, 10 questions, timer values, star thresholds, badge id). |
| `SubjectData.cs` | ScriptableObject | One subject (Addition / Time / …) holding an ordered list of LevelData. Also the `MathSubject` enum. |
| `GradeData.cs` | ScriptableObject | One grade (1/2/3) holding subjects. |
| `MathDatabase.cs` | ScriptableObject | Root container with all grades. Exposes lookup helpers `GetGrade`, `GetSubject`, `GetLevel`. |
| `PlayerProfile.cs` | serializable class | The single saved profile — name, avatar, stars, XP, badges, subject stats, settings, play-day streak. |
| `GameSession.cs` | serializable class | Transient selection between scenes + `SessionResult` snapshot for the Results screen. |
| `AvatarData.cs` | ScriptableObject | One avatar (id, display name, optional sprite, emoji, tint). |
| `AvatarLibrary.cs` | ScriptableObject | Ordered list of avatars + `BuildDefault()` runtime fallback. |
| `UITheme.cs` | ScriptableObject | Sprite + colour overrides — drop sprites here to reskin the entire UI. |
| `VFXLibrary.cs` | ScriptableObject | GameObject prefab slots for Epic Toon FX correct/wrong/win/star/etc. |

### `Utility/`

| File | Purpose |
|---|---|
| `QuestionGenerator.cs` | Pure-functional question factory. `Generate(grade, subject, level)` returns a `List<MathQuestion>`. Used by the editor menu and the runtime fallback. |
| `DatabaseBootstrapper.cs` | `BuildInMemory()` constructs a full `MathDatabase` SO instance at runtime. Also owns the subject-themed `StoryIntro/Outro` templates. |
| `SaveSystem.cs` | JSON ⇄ file persistence with a PlayerPrefs mirror as a safety net. |

### `Managers/`

All are MonoBehaviours added as components on the singleton GameObject
created by `GameManager.Instance`. Add a new manager by:

1. Adding the field `public NewManager New { get; private set; }` to `GameManager`.
2. Adding `New = gameObject.AddComponent<NewManager>(); New.Init(Profile);` in `GameManager.Initialize`.

| File | Purpose |
|---|---|
| `GameManager.cs` | Root singleton. Holds Profile, Session, Database, AvatarLibrary, child managers. |
| `AudioManager.cs` | Named SFX dictionary + procedural fallbacks + music volume control. |
| `HapticManager.cs` | **Static** — no MonoBehaviour. `Light/Medium/Heavy()` gated on `PlayerProfile.hapticsOn`. |
| `ProgressManager.cs` | `CompleteLevel(...)` returns SessionResult, awards badges, persists profile. Static `PrettyBadgeName(id)`. |
| `UIManager.cs` | Scene transitions with fade. `Go(sceneName)`, `ParentSceneOf(sceneName)`. |
| `VFXManager.cs` | Optional Epic Toon FX particle hooks. Silent no-ops when `VFXLibrary` is missing. |
| `PlayerSetupManager.cs` | First-launch screen logic (not a singleton — lives on `[SceneRoot]` of PlayerSetup.unity). |
| `SettingsManager.cs` | Settings scene logic. |
| `ParentalDashboardManager.cs` | Parental Dashboard scene logic (PIN gate + dashboard). |

### `Modes/`

One MonoBehaviour per scene. Each lives on the scene's `[SceneRoot]`.

| File | Scene | Inherits from |
|---|---|---|
| `BootstrapManager.cs` | Bootstrap.unity | MonoBehaviour |
| `MainMenuManager.cs` | MainMenu.unity | MonoBehaviour |
| `LevelSelectManager.cs` | LevelSelect.unity | MonoBehaviour |
| `ModeSelectManager.cs` | ModeSelect.unity | MonoBehaviour |
| `LearnModeManager.cs` | LearnMode.unity | MonoBehaviour |
| `PracticeModeManager.cs` | PracticeMode.unity | `GameplayManagerBase` |
| `QuizModeManager.cs` | QuizMode.unity | `GameplayManagerBase` |
| `StoryModeManager.cs` | StoryMode.unity | `GameplayManagerBase` |
| `SpeedRoundManager.cs` | SpeedRound.unity | `GameplayManagerBase` |
| `ResultsManager.cs` | Results.unity | MonoBehaviour |

### `Gameplay/`

| File | Purpose |
|---|---|
| `GameplayManagerBase.cs` | Abstract base — builds the question card / answer grid / hint row / pause button, runs the MCQ loop, fires correct/wrong audio + VFX + haptics, tracks streak, calls `ProgressManager.CompleteLevel` and routes to Results. Subclasses override `HeaderTitle`, `HeaderColor`, `ShowHint`, `StopOnFirstWrong`, `AllowPause`, `TargetQuestionCount`. |

### `UI/`

| File | Purpose |
|---|---|
| `UIFactory.cs` | Procedural Canvas / TMP / Layout builder. Every screen calls these. Theme-aware. |
| `UIThemeService.cs` | Lazy Resources lookup for a `UITheme.asset` — used by `UIFactory`. |
| `DefaultSprite.cs` | Procedural sprite cache (rounded rect, gradient, circle, solid). Generated on demand when no UITheme is present. |
| `SafeAreaHandler.cs` | Resizes a RectTransform to `Screen.safeArea` every frame — handles notched devices. |
| `FadeOverlay.cs` | Persistent DontDestroyOnLoad Canvas used by `UIManager.Go(...)` for fade-to-black transitions. |
| `AnswerButton.cs` | One MCQ answer button. Spawn helper + correct/wrong flash. |
| `StarRating.cs` | Star count widget using TMP glyphs (kept for legacy uses). |
| `ProgressBar.cs` | Simple 0..1 fill bar with adjustable colour. |
| `Timer.cs` | Countdown widget with threshold colours + pulse + tick SFX. |
| `AnimatedFeedback.cs` | "✓ Correct!" / "✗ Try again" pill that pops and fades. |
| `QuestionVisualRenderer.cs` | Renders the visual hint per `MathQuestion.visual` enum: dots, clock, fraction pie, pattern, money, etc. |
| `ToggleSwitch.cs` | Mobile-friendly on/off switch with sprite-aware mode. |
| `AvatarTile.cs` | One tile in the PlayerSetup avatar grid. |
| `AccuracyBarChart.cs` | Horizontal bar chart for the Parental Dashboard. |
| `PasswordDialog.cs` | Modal PIN prompt with cancel/OK. Used by Settings PIN-change flow and Reset Progress. |

### `Editor/`

| File | Menu item |
|---|---|
| `DatabaseBuilderMenu.cs` | **MathEdu → Build Default Database**, **MathEdu → Build Default Avatar Library**, **MathEdu → Wipe Generated Database**, **MathEdu → Reset Player Progress** |
| `SceneBuilderMenu.cs` | **MathEdu → Build All Scenes** |

## 5. ScriptableObject hierarchy

```
MathDatabase                       (root SO)
└── List<GradeData> grades         (3 entries)
    └── List<SubjectData> subjects (8 / 9 / 9 entries depending on grade)
        └── List<LevelData> levels (20 entries each)
            └── List<MathQuestion> questions  (10 entries — plain class, not SO)
```

### Stable ids

Every LevelData has a stable id `g{gradeNum}_{subject}_l{lvl}`, e.g.
`g1_addition_l3`. The id is the save key — `PlayerProfile.levelProgress`
is a flat list keyed by it.

### Lookups

`MathDatabase.GetGrade(N)`, `GetSubject(N, MathSubject)`,
`GetLevel(N, MathSubject, M)` all return `null` when missing. The
gameplay managers never iterate the tree directly — they read the
current selection from `GameManager.Session`.

## 7. `Resources/` — auto-loaded assets

`Resources.Load<T>("filenameWithoutExtension")` is how the runtime
discovers assets without inspector references. The project uses it for:

| File path under `Assets/Resources/` | Loaded by | Purpose |
|---|---|---|
| `MathDatabase.asset` | `GameManager.EnsureDatabase()` | Real database (skip runtime procedural fallback) |
| `AvatarLibrary.asset` | `GameManager.EnsureAvatarLibrary()` | 10 designer-authored avatars |
| `UITheme.asset` | `UIThemeService.Theme` | Sprite overrides for the entire UI |
| `VFXLibrary.asset` | `VFXManager.Init()` | Epic Toon FX particle prefabs |
| `Audio/sfx_correct.wav` etc. | `AudioManager.TryLoadFromResources()` | Override procedural SFX with real .wav clips |

> ⚠️ Anything under `Resources/` is **always included in the build** even
> if nothing references it. Keep the folder lean — don't dump unused
> assets there.

## 8. `Sprites/` and theming

```
Assets/Sprites/
├── Backgrounds/      ← background PNGs for menu / play / results / etc.
├── UI/               ← buttons, panels, toggles, sliders (Layer Lab pack)
└── Characters/       ← avatar sprite art (if you want to replace emoji)
```

### Wiring sprites into the UI

1. Right-click in the Project window → **Create → MathEdu → UI Theme**.
2. Drag your sprites into the matching slots on the new `UITheme.asset`
   (e.g. `buttonSprite`, `panelSprite`, `menuBackground`, `toggleOnSprite`).
3. Move (or copy) the configured asset to `Assets/Resources/UITheme.asset`.
4. Press Play. The entire UI now uses your sprites.

The fallbacks are procedural (rounded rectangles from `DefaultSprite`)
so missing slots never break the layout.

## 9. Procedural UI philosophy

**Every screen is built in code via `UIFactory`.** A typical Build method
looks like:

```csharp
private void Build()
{
    var (canvas, safe) = UIFactory.CreateCanvas("[MyCanvas]");
    UIFactory.CreateThemedBackground(safe, "menu");

    var header = UIFactory.CreatePanel(safe,
        new Vector2(0, 0.88f), new Vector2(1, 1f),
        UIFactory.Primary, 0, "Header");
    UIFactory.CreateText(header, "My Screen", 56, Color.white,
        TextAlignmentOptions.Center, "Title").fontStyle = FontStyles.Bold;

    // … etc.
}
```

### Why procedural?

- **Tiny .unity files** — no merge conflicts on layout.
- **Theme-aware** — `UIFactory` consults `UIThemeService` for every Sprite
  slot. Reskin via a single asset.
- **Safe-area aware** — `UIFactory.CreateCanvas` adds a `SafeAreaHandler`
  child so notch / dynamic-island devices look right automatically.
- **Test-friendly** — no Awake-time reference resolution to break.

### UIFactory helpers (most-used)

| Helper | Returns | Use for |
|---|---|---|
| `CreateCanvas(name)` | (Canvas, SafeArea RectTransform) | Root of every screen |
| `CreatePanel(parent, anchorMin, anchorMax, color, cornerRadius, name)` | RectTransform | Boxes / cards |
| `CreateText(parent, text, size, color, align, name)` | TextMeshProUGUI | Any TMP text |
| `CreateButton(parent, label, bgColor, fontSize, name)` | Button | CTA buttons |
| `CreateIconButton(parent, icon, bgColor, name)` | Button | Small icon buttons (back, settings) |
| `CreateInputField(parent, placeholder, fontSize, name)` | TMP_InputField | Single-line input |
| `CreateSlider(parent, initialValue, name)` | Slider | Volume sliders |
| `CreateVerticalLayout(parent, spacing, padding, name)` | GameObject | Column layouts |
| `CreateHorizontalLayout(parent, spacing, padding, name)` | GameObject | Row layouts |
| `CreateGridLayout(parent, cellSize, spacing, constraintCount, name)` | GameObject | Grids |
| `CreateScrollView(parent, name)` | ScrollRect | Scrollable content |
| `CreateThemedBackground(parent, key)` | Image | Background sprite or gradient |

## 10. Save data on disk

`PlayerProfile` is serialised to JSON by `SaveSystem`.

### File path

```
Application.persistentDataPath / player_profile.json
```

On Android: `/data/data/com.mathedu.game/files/player_profile.json`.
On iOS: `Library/.../Documents/player_profile.json`.
In Editor (Windows): `%userprofile%/AppData/LocalLow/<Company>/<Product>/player_profile.json`.

### PlayerPrefs mirror

For platforms with occasional file-IO flakes, the same JSON is mirrored
into two PlayerPrefs keys (`mathedu.profile` and `mathedu.profile.backup`).
`SaveSystem.Load` tries the file first, then PlayerPrefs, then returns a
fresh `PlayerProfile`.

### Reset

`SaveSystem.DeleteAll()` removes both the file and the PlayerPrefs keys.
The editor menu **MathEdu → Reset Player Progress** calls this.

## 11. Editor menus

```
MathEdu / Build Default Database         ← Creates ~6,600 questions
MathEdu / Build Default Avatar Library   ← Creates 10 avatars
MathEdu / Build All Scenes               ← Creates 13 .unity files
MathEdu / Wipe Generated Database        ← Deletes the generated tree
MathEdu / Reset Player Progress          ← Wipes save file + PlayerPrefs
```

The menu is in `Assets/Scripts/Editor/DatabaseBuilderMenu.cs` and
`Assets/Scripts/Editor/SceneBuilderMenu.cs`. Order is intentional —
priority numbers `10, 12, 5, 20, 30` group "create" actions before
"destructive" ones in the Unity menu rendering.

## 12. Packages — what's allowed and what isn't

`Packages/manifest.json` is the source of truth. Everything in it should
be **either** a stock `com.unity.modules.*` package **or** one of:

- `com.unity.collab-proxy` — Unity Collaborate (harmless if unused)
- `com.unity.ide.rider`, `com.unity.ide.visualstudio`, `com.unity.ide.vscode` — IDE bridges
- `com.unity.test-framework` — for Editor tests
- `com.unity.textmeshpro` — required (we use TMP everywhere)
- `com.unity.timeline` — Unity-shipped
- `com.unity.ugui` — Unity-shipped UI

**Forbidden:**

- DOTween, Lean Tween, etc. — tweens are implemented as coroutines.
- Json.NET, Newtonsoft, etc. — `JsonUtility` is sufficient.
- Any asset-store haptics SDK — we use `Handheld.Vibrate()`.
- Anything from the Asset Store that's not a sprite/audio asset.

If you add a package, the project no longer matches the task brief and
the merge to `main` should be rejected.

## 13. Adding new content (cookbook)

### Add a new subject

1. Add a value to `MathSubject` enum in `SubjectData.cs`.
2. Add a generator method in `QuestionGenerator.cs` (return
   `List<MathQuestion>` for a given grade + level).
3. Add to the appropriate `SubjectsFor(grade)` array.
4. Add an emoji in `DatabaseBootstrapper.EmojiForSubject`.
5. Add a theme colour in `DatabaseBootstrapper.ThemeForSubject`.
6. Add story templates in `DatabaseBootstrapper.StoryIntro` and
   `StoryOutro`.
7. Run **MathEdu → Build Default Database** to materialise the new SOs.

### Add a new question visual

1. Add a value to `QuestionVisual` enum in `MathQuestion.cs`.
2. Add a `case` in `QuestionVisualRenderer.Show(q)` that calls a new
   `DrawXxx(q)` method.
3. Have your generator emit `q.visual = QuestionVisual.Xxx` and the
   relevant `q.visualPayload[]`.

### Add a new mode

1. Create a new MonoBehaviour `MyNewModeManager : GameplayManagerBase`
   in `MathEdu.Modes`. Override `HeaderTitle`, `HeaderColor`, and
   whichever behavioural flags you want (e.g. `StopOnFirstWrong`,
   `AllowPause`, `TargetQuestionCount`).
2. Add a const `SceneMyNewMode = "MyNewMode"` to `UIManager`.
3. Add a value to `LearningMode` enum in `GameSession.cs`.
4. Add the mode card in `ModeSelectManager.Build`.
5. Add the scene + manager pair to the `Scenes` array in
   `SceneBuilderMenu.cs`.
6. Run **MathEdu → Build All Scenes**.

### Add a new badge

1. Decide on a badge id (e.g. `streak_master`).
2. Add the award rule in `ProgressManager.MaybeAwardMetaBadges`.
3. Add the pretty name in `ProgressManager.PrettyBadgeName`.
4. (Optional) Add unlock-trigger fields to `PlayerProfile` if you need
   to track new state (cf. `speedRoundBestStreak`).

### Add a new avatar

1. Right-click in the Project window → **Create → MathEdu → Avatar Data**.
2. Fill in `avatarId`, `displayName`, `emoji`, `tint`. Optionally drag a
   `Sprite` into the `sprite` slot.
3. Drag the new `AvatarData` asset into the `avatars` array on
   `AvatarLibrary.asset`.
4. Move (or copy) the updated `AvatarLibrary.asset` to
   `Assets/Resources/AvatarLibrary.asset` so the runtime picks it up.

## Final word

The project optimises for **clarity over scaffolding** and **runtime
fallbacks over wiring requirements**. You should be able to land a new
content category — a new subject, a new mode, a new badge — without
opening a single `.unity` file in the Hierarchy. If you find yourself
hand-editing scene YAML, you've probably missed a helper in `UIFactory`
or a hook in `GameplayManagerBase`.
